### [C1] web/src/App.tsx:383 + :393 — Hooks 顺序违规导致登录/退出必然白屏

- **Severity: Critical**
- **Root Cause**: 违反 Rules of Hooks——条件 early return 之后调用了 `useMemo`
- **Impact**: 整个应用根节点被 React 卸载，白屏，只能手动刷新

[App.tsx:383](file:///E:/AAAProject/ClipVault/web/src/App.tsx#L383) 是 `if (!authed) { return <KeyGate/> }`，而 [App.tsx:393](file:///E:/AAAProject/ClipVault/web/src/App.tsx#L393) 的 `const usableToolbarPlugins = useMemo(...)` 在它**之后**。于是 `authed` 翻转时 Hook 数量变化：

| 路径              | Hook 数变化 | React 抛错                                               |
| --------------- | -------- | ------------------------------------------------------ |
| 登录 `false→true` | 16 → 17  | `Rendered more hooks than during the previous render.` |
| 退出 `true→false` | 17 → 16  | `Rendered fewer hooks than expected.`                  |

[main.tsx:6-10](file:///E:/AAAProject/ClipVault/web/src/main.tsx#L6-L10) 直接 `render(<StrictMode><App/></StrictMode>)`，**没有任何 error boundary**，所以渲染期抛错 = 整棵树卸载。

回归来源：`git log -S` 定位到 `7dbf6c7 feat: 插件系统新增信任机制与安全提示`——early return 自 M1-M3 就存在，`useMemo` 是后来加到它下面的。

**Evidence**（jsdom + react/react-dom 19.3.0，按 App.tsx 结构 1:1 复刻 Hook 序列）：

```
登录方向:
  P1 initial (authed=false): KeyGatelogin
  P2 after login          :            <-- 内容全空
  17. undefined                 useMemo
     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  Error: Rendered more hooks than during the previous render.
      at updateWorkInProgressHook (react-dom-client.development.js:8224:17)
  root unmounted (blank page)? true

退出方向:
  P1 initial (authed=true) : main:0-0logout
  P2 after logout          : ""
  Error: Rendered fewer hooks than expected. This may be caused by an accidental early return statement.
      at finishRenderingHooks (react-dom-client.development.js:8093:15)
  root unmounted (blank page)? true
```

React 源码 `react-dom-client.development.js:8219-8224` 确认这是无条件抛出：

```js
if (null === nextCurrentHook) {
  if (null === currentlyRenderingFiber.alternate) throw Error("Update hook called on initial render...");
```

**为什么日常没被发现**：`useState(hasApiKey())` 读的是 localStorage。首次登录白屏后刷新，key 已落盘 → 首帧即 `authed=true` → Hook 数恒定 → 一切正常。所以只有「全新设备首次登录」和「点退出」两条路径会炸，而刷新就能掩盖。

### [C2] server/src/ws.ts:31-35 — 单个非法 WebSocket 帧击穿整个服务进程

- **Severity: Critical**
- **Root Cause**: 缺失 `error` 事件监听器（EventEmitter 无监听器时 `emit('error')` 直接 throw）
- **Impact**: Node 进程退出，所有设备掉线、在途请求全部失败

[ws.ts:31-35](file:///E:/AAAProject/ClipVault/server/src/ws.ts#L31-L35) 里 `wss.handleUpgrade(...)` 回调只挂了 `ws.on('pong')`，然后 `wss.emit('connection', ws, req)`——但全仓库**没有任何 `wss.on('connection')` 监听器**（`grep -rn "on('error'\|on('connection'" server/src/` → `NONE FOUND`），所以也没有任何地方能挂上 error handler。

`ws@8.21.3` 的 `lib/websocket.js:1201-1219 receiverOnError` 会执行 `websocket.emit('error', err)`。

**Evidence**（真实启动服务端，原始 TCP 完成握手后发一个未掩码帧）：

```
[1] handshake response first line: HTTP/1.1 101 Switching Protocols
[2] server DEAD after bad WS frame -> ECONNREFUSED
[3] failed -> ECONNREFUSED
[4] failed -> ECONNREFUSED

=== server log ===
node:events:487
      throw er; // Unhandled 'error' event
RangeError: Invalid WebSocket frame: MASK must be set
    at Receiver.getInfo (ws/lib/receiver.js:351:28)
Emitted 'error' event on WebSocket instance at:
    at Receiver.receiverOnError (ws/lib/websocket.js:1218:15)
  code: 'WS_ERR_EXPECTED_MASK'
```

探针 2/3/4 全部 `ECONNREFUSED`——HTTP 侧也一起死了，因为整个进程没了。

触发门槛很低：任何持 API Key 的客户端发一个畸形帧即可；更常见的是移动端弱网、反代缓冲区问题导致帧损坏。Docker `restart: unless-stopped` 会拉起，但每次崩溃都是一次全站中断。

**Fix**: 在 `handleUpgrade` 回调内加 `ws.on('error', () => {})`（或记录日志后吞掉），并建议同时加 `wss.on('connection', (ws) => { ws.on('error', ...) })`。另可加 `process.on('uncaughtException')` 兜底，但根因是缺 error 监听器。

### [M8] server/src/ws.ts:15-16 + web/src/ws.ts:15 — API Key 经 URL query string 传输

服务端 [ws.ts:15-16](file:///E:/AAAProject/ClipVault/server/src/ws.ts#L15-L16) 支持 `url.searchParams.get('key')`，客户端 [ws.ts:15](file:///E:/AAAProject/ClipVault/web/src/ws.ts#L15) 正是这么用的：

```js

```

浏览器 WebSocket API 不支持自定义 header，所以这有一定客观原因。但 key 会进入浏览器历史、`Referer`、以及任何中间反代的 access log。当前 [build/caddy/Caddyfile](file:///E:/AAAProject/ClipVault/build/caddy/Caddyfile) 没有开启 `log`，所以本地部署影响有限——**但一旦加上访问日志或换成别的反代就会明文落盘**。这是整站唯一的鉴权凭据。

**Fix**: 改为握手后首帧鉴权（连接后发一条 `{type:'auth', key}`，超时未鉴权则关闭），或签发短期一次性 ticket 用于 WS 握手。至少在 Caddyfile 里显式对 `/ws` 关闭 query 记录。
