# 规格说明书：web+server 合并单容器架构

日期：2026-10-25
状态：已实施（2026-10-25 本地构建+功能验证通过，待前端 UI 验证与 fnos 生产迁移）

## 1. 问题陈述

当前 Docker 部署为三容器结构：

- `server`：Node.js API + WS（Express 5 + better-sqlite3），纯 API，无静态服务能力，监听 3000；
- `web`：一次性容器，构建 Vite 产物后 `cp` 进共享 volume `web-dist` 即退出（`restart: "no"`）；
- `caddy`：从 `web-dist` 卷托管静态文件 + SPA fallback，`/api/*` 与 `/ws` 反代到 server:3000，`encode gzip`，对外暴露唯一端口。

问题：web 容器"cp 完退出"是为绕开单容器静态托管而引入的非常规设计；`web-dist` 共享卷与 `service_completed_successfully` 条件依赖属于时序 hack；三容器运维心智与故障面大于实际收益。

本次变更：web 与 server 合并为**单容器**，Node 自持静态服务；caddy 降级为可选的 proxy 扩展位。三容器 → 一容器。

**重要前提（2026-10-25 用户澄清）**：本服务是**公网暴露或隧道暴露公网**对真实用户提供服务的，不是纯内网自用。所有安全与压缩决策按公网服务标准评估。

## 2. 方案概述

- 一个多阶段 Dockerfile 同时构建 web（Vite 产物）与 server（tsc + prune），运行时层将静态产物放 `/app/public`，server 用 `express.static` 托管并做 SPA fallback。
- server 新增 `compression` 中间件（运行时 gzip，覆盖静态与 API 响应，替代原 caddy `encode gzip`）。
- 静态服务挂在 Bearer 鉴权中间件**之前**（现状 `app.use(auth)` 全局强制鉴权，静态文件必须匿名可达）；SPA fallback 显式跳过 `/api/*` 与 `/ws`。
- compose 收敛为单服务 `app`（服务名由 `server` 改名，容器名变 `clipnote-app-1`）；数据卷名 `clipnote-data` 不变。
- 新增可选扩展文件 `docker-compose.proxy.yml` + 重写的 `caddy/Caddyfile`（默认 `:80` 纯反代，置顶 TLS 模板），未来接 HTTPS/域名时叠加启用，应用零改动。
- server 加 `app.set('trust proxy', 1)` 预埋，未来反代后真实 IP 正确。

## 3. 已定决策

| 决策 | 内容 | 出处 |
|---|---|---|
| D1 目标拓扑 | 1 容器（去 caddy，Node 自持全部），而非 2 容器保 caddy | 拷问 Q1–Q3：对比拓扑优劣；用户关切网络拓展与安全，结论是单端口自持应用 + 可选反代扩展位两头兼顾，且"保 caddy"存在启动竞态硬伤（失去 `service_completed_successfully` 保障） |
| D2 安全影响评估 | 去掉 caddy 换 `express.static` 不构成实质安全降级：`serve-static`/`send` 与 caddy 同为成熟防御路径穿越的组件；真实安全边界（API_KEY、zod 校验、json limit）全在应用层不受影响；caddy 现状也未提供 TLS/限流/WAF。公网定位下补充：确认 Node 默认 `requestTimeout`/`headersTimeout` 生效防 slowloris | 拷问 Q4 |
| D3 gzip 方案 | `compression` npm 中间件运行时 gzip（静态 + API 均覆盖），与原 `encode gzip` 行为最接近；公网带宽收益明显，NAS 小流量 CPU 开销可忽略。否决：构建期预压缩（改动面大、API 不压缩）、不压缩（公网传输体积 +60~70%） | 拷问 Q5 |
| D4 构建上下文 | 单 context 含两子目录：`build/app/{Dockerfile,server/,web/}`。否决 `additional_contexts`（要求 Docker Engine 23+/compose 2.17+，fnOS NAS 版本未知有兼容风险）与源码平铺合并（两份 package.json 管理混乱） | 拷问 Q6 |
| D5 扩展位形态 | 预写 TLS 模板：`docker-compose.proxy.yml`（可选叠加）+ `caddy/Caddyfile`（默认 `:80` 纯反代，置顶注释含域名 TLS 模板，启用即自动 HTTPS）。未来启用零思考成本 | 拷问 Q7 |
| D6 服务命名 | compose 服务名 `server` → `app`（现兼任静态服务，语义更准）。容器名变 `clipnote-app-1`；卷实体 `clipnote_clipnote-data` 不变 | 拷问 Q8 |
| D7 生产迁移 | 我（agent）执行：本地部署区验证 → 同步 fnos → `up -d --build` → 验证 → 孤儿卷清理前列清单征求用户确认 | 拷问 Q9 |
| D8 静态与鉴权边界 | 静态服务 + SPA fallback 挂载于 `app.use(auth)` 之前；fallback 路径跳过 `/api/*` 与 `/ws`（未知 `/api` 路径仍走 JSON 404，不落 index.html） | 探究发现：`app.use(auth)` 现状全局强制 Bearer，静态文件能匿名访问全靠 caddy 绕行 |

## 4. 改动清单

### 4.1 `build/app/Dockerfile`（新建）

```
stage 1 (web-build):  ${NODE_IMAGE}
  COPY web/package.json web/package-lock.json → npm ci
  COPY web 源码（tsconfig、vite.config.*、index.html、src/、public/）
  RUN npm run build                          → /app/dist

stage 2 (server-build): ${NODE_IMAGE}
  COPY server/package.json server/package-lock.json → npm ci --ignore-scripts
  COPY server/tsconfig.json server/src/
  RUN npm run build && npm prune --omit=dev

stage 3 (runtime): ${NODE_IMAGE}
  ENV NODE_ENV=production DATA_DIR=/data
  COPY --from=server-build node_modules → /app/node_modules
  COPY --from=server-build dist        → /app/dist
  COPY --from=web-build /app/dist      → /app/public
  VOLUME /data
  EXPOSE 3000
  CMD ["node", "dist/index.js"]
```

保留原注释要点：better-sqlite3 v13+ 为 N-API 预编译，`--ignore-scripts` 规避 node-gyp。

### 4.2 `scripts/build.sh`

- 步骤 2 组装上下文改为：`build/app/` 下建 `server/`、`web/` 子目录，拷贝清单不变（server：.dockerignore→app 级、package.json/lock、tsconfig、src/；web：package.json/lock、tsconfig、vite.config.*、index.html、src/、public/）；app 级 `.dockerignore` 与 `Dockerfile` 为常驻文件（同 compose 的"脚本不覆盖、仅校验"策略）。
- 步骤 3 校验项：`docker-compose.yml`、`docker-compose.cn.yml`、`docker-compose.proxy.yml`、`caddy/Caddyfile`、`app/Dockerfile`。
- 收尾文件清单输出 `build/app/` 结构。

删除：`web` 服务、`caddy` 服务、`web-dist`/`caddy-data`/`caddy-config` 卷、全部 `depends_on`（`ALPINE_IMAGE` 参数亦不再需要）。

### 4.4 `build/docker-compose.proxy.yml`（新建）

可选叠加文件，平时不启用：

```yaml
services:
  caddy:
    image: ${CADDY_IMAGE:-caddy:2-alpine}        # cn 版注释给出 DaoCloud 源
    ports:
      - "${CLIPNOTE_PORT:-31291}:80"
    volumes:
      - ./caddy/Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
      - caddy-config:/config
    depends_on:
      - app
    restart: unless-stopped

volumes:
  caddy-data:
  caddy-config:
```

注：启用 proxy 时主 compose 的 `ports` 需让位给 caddy（启用方式与端口处理写在文件头注释里）。

### 4.5 `build/caddy/Caddyfile`（重写）

- 置顶注释：TLS 模板 `your.domain.com { reverse_proxy app:3000 }`（Caddy 自动签发续期证书），并注明需要 443 可达。
- 默认站点块 `:80 { reverse_proxy app:3000 }`（caddy 对 WS 自动透传升级头，无需显式配置）。

### 4.6 `server/src/index.ts`

中间件挂载顺序（关键变更）：

```ts
import compression from 'compression';

const app = express();
app.disable('x-powered-by');            // 现状已有
app.set('trust proxy', 1);              // 新增预埋：未来反代后真实 IP/转发头正确
app.use(compression());                 // 新增：替代 caddy encode gzip

const publicDir = config.publicDir;     // config.ts 新增 publicDir，env PUBLIC_DIR，默认 './public'（dev） 
app.use(express.static(publicDir, { index: 'index.html', dotfiles: 'ignore' }));

// SPA fallback：跳过 /api/* 与 /ws，其余 GET 落 index.html
app.use((req, res, next) => {
  if (req.method !== 'GET' || req.path.startsWith('/api') || req.path === '/ws') return next();
  res.sendFile(join(publicDir, 'index.html'));
});

app.use(express.json({ limit: '2mb' })); // 现状已有
app.use(auth);
app.use('/api/clipboards', ...);         // 现状不变
app.use(errorHandler);
```

静态与 fallback 置于 auth 之前的原因见 D8。config.ts 新增 `publicDir` 读取（默认值兼容本地 dev：dev 时该目录不存在，`express.static` 对不存在目录正常 fallthrough，dev 流程不受影响）。

### 4.7 `server/package.json`

`dependencies` 新增 `compression`（+ devDependencies 的 `@types/compression`）。

## 5. 验证方案

1. `scripts/build.sh` 重新组装 build/，确认目录结构与校验通过。
2. 本地 `cd build && docker compose up -d --build`：单容器启动成功。
3. 功能验证：
   - `curl http://localhost:31291/` 返回 index.html（匿名可达）；
   - 深链接 SPA fallback（如 `/some/route`）返回 index.html；
   - 无 Authorization 头请求 `/api/clipboards` 返回 401 JSON（鉴权未被静态旁路）；
   - 带 key 请求 API 正常；`/ws` 握手正常；
   - 未知 `/api/xxx` 返回 JSON 404 而非 index.html；
   - 响应头含 `Content-Encoding: gzip`（文本类资源）；
   - 插件上传、剪贴板 CRUD 抽查（前端 UI 由用户按惯例验证）。

## 7. 遗留项（不在本次范围）

- **WS 鉴权走 URL query**（审计 H 级项）：公网暴露定位下权重升高，建议列入后续挑修清单（握手后首帧鉴权或短期 ticket）。若未来启用 proxy 的 access log，key 会明文落盘，届时务必先修此项或对 `/ws` 关闭 query 日志。
- 未来公网裸端口（非隧道）场景：尽早启用 proxy 扩展位上 TLS；若走 Cloudflare Tunnel / frp+TLS，则扩展位继续待命。
- 限流/CSP（审计 Low 级项）本次不引入。
