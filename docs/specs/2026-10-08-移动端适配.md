# Spec：Web 前端移动端适配

> 日期：2026-10-08
> 状态：已对齐，待拆分
> 术语：见 [CONTEXT.md](../../CONTEXT.md)；检测策略决策：见 [ADR-0001](../adr/0001-移动端特征综合判定.md)

## 1. 问题陈述

ClipNote Web 前端是纯桌面布局：剪切板侧边栏常驻、条目操作按钮依赖悬停显示（`ClipboardItem.css:85`）、添加区依赖 Enter 键与"添加"按钮。手机浏览器打开时侧边栏挤占屏幕、悬停操作在触屏上完全不可见、底部操作区错位，基本不可用。需要在识别到移动端模式后让界面自适应，同时桌面模式行为零变化。

## 2. 方案概述

- 新增一个**移动端模式检测模块**：以 `pointer: coarse` + `maxTouchPoints` 为主、UA 为辅做特征综合判定，结果以根节点 class（`mobile`）为唯一信号源暴露给 CSS 与 React（ADR-0001）。
- 移动端模式下：侧边栏变为**抽屉式侧边栏**，条目操作改为**常驻复制 + 长按弹出底部动作面板**，添加区隐藏"添加"按钮、输入框占满整行。
- 次级页面（设置/插件/各弹窗）仅做安全边距与宽度的最小 CSS 修正。
- 桌面模式所有现有行为、样式、交互不变；移动端适配不删除任何功能。

## 3. 用户故事

### 检测

- **U1**：以手机（coarse pointer + 触摸 + 移动 UA）访问时，根节点携带 `mobile` class，界面呈现移动端布局。
- **U2**：以 iPad Safari（默认桌面 UA）访问时，因触摸特征被判定为移动端模式，界面呈现移动端布局。
- **U3**：桌面浏览器把窗口缩窄到手机宽度时，不出现移动端布局（判定与视口宽度无关）。
- **U4**：桌面模式（fine pointer、无触摸）下，根节点无 `mobile` class，所有现有行为不变。

### 布局

- **U5**：移动端模式下条目列表占满全屏；点侧边栏切换按钮后**抽屉式侧边栏**滑出覆盖在列表之上（含遮罩），选择剪切板或点遮罩后抽屉收起。
- **U6**：移动端模式下 Header 仍提供侧边栏切换、设置、插件入口，按钮触控目标足够大（≥ 40×40px 视觉区域）。

### 条目交互

- **U7**：移动端模式下每条条目上**常驻复制**按钮始终可见，点击即复制并呈现现有复制成功反馈。
- **U8**：移动端模式下**长按条目**（约 500ms）弹出**底部动作面板**，含：复制、编辑、插件（有启用插件时）、删除四项操作，行为与桌面端对应操作一致。
- **U9**：底部动作面板可点遮罩或取消关闭；弹出期间不触发条目的其他交互；长按不应同时触发 iOS/Android 的文本选择放大镜（条目在移动模式下抑制长按选中）。
- **U10**：移动端模式下条目列表为单列全宽展示，条目内容正常换行，无横向滚动。

### 添加区

- **U11**：移动端模式下添加区隐藏"添加"按钮与展开按钮，输入框占满整个 footer 模块；软键盘回车仍可添加（沿用现有 Enter 逻辑）。
- **U12**：未选剪切板时输入框的禁用态与占位文案在移动端保持现有语义。

### 次级页面

- **U13**：移动端模式下设置页、插件页、编辑弹窗、插件确认弹窗、重复检查分组展示在安全边距内可用，无横向滚动、无元素被裁切；不重新设计。

## 4. 已定决策

| 决策 | 结论 |
|------|------|
| 适配范围 | 布局 + 交互适配，功能不减，不做移动专属功能删减 |
| 检测策略 | 特征综合判定（ADR-0001）：`pointer: coarse` + `maxTouchPoints` + UA → 根节点 class 唯一信号源；禁止各组件独立检测 |
| 移动布局 | 抽屉式侧边栏（非双 tab、非底部导航） |
| 条目操作 | 长按 → 底部动作面板；常驻复制弥补可发现性（非点按展开、非纯长按） |
| 添加区 | 隐藏"添加"按钮，输入框占满整行，软键盘回车添加 |
| 次级页面 | 最小修正，不专门重设计 |

## 5. 测试决策

接缝选择：**检测模块**是最稳定的接缝——纯函数输入（matchMedia / navigator 特征 / UA 字符串）→ 输出布尔值，可单元测试；UI 适配走根节点 class，可集成断言。

- **单元测试**：检测模块对典型特征组合的判定——iPhone/iPad Safari（桌面 UA + 触摸 → true）、Android Chrome（true）、桌面 Chrome/Firefox（false）、触屏笔记本（true，接受的代价，见 ADR-0001）。
- **组件/集成测试**：`mobile` class 存在时——条目操作按钮常驻、添加按钮不渲染、长按触发动作面板回调。
- **手动验收**（移动端 UI 无法自动化模拟的部分，按用户既有习惯给出最小复现路径）：
  - DevTools 设备模拟（iPhone 15 Pro / iPad）验证 U1、U2、U5–U13；
  - 桌面窗口缩窄验证 U3（仍是桌面布局）；
  - 桌面正常操作回归验证 U4（悬停操作、添加按钮均不变）。
- **"完成"的定义**：上述测试通过 + 桌面端视觉与交互与改动前无差异（对照现有截图/行为）。

## 6. 明确不做

- 不做底部导航栏、双 tab 等导航重构
- 不做移动专属的功能隐藏或降级（设置/插件入口保留）
- 不做设置页、插件页的专门重设计（仅安全边距级修正）
- 不做纯视口宽度的响应式断点体系（除现有两处 media query 维持现状外，适配一律挂在 `mobile` class 下）
- 不做横竖屏切换的专门优化
- 不做 PWA、安装提示等移动增强

## 7. 补充说明

- `web/index.html` 已有 viewport meta，无需改动。
- 长按与文本选择冲突：移动模式下条目需抑制长按选中（`-webkit-user-select` / `user-select` 处理），但编辑态输入框内仍需可正常选择文本。
- 长按判定需容忍轻微手指位移（阈值约 10px），避免触屏抖动导致长按失效；长按期间若触发滚动（touchmove 超阈值）应取消。
- 现有 `.menu-toggle` / `.menu-action`（ClipboardList 顶部菜单）为点击式，移动端可直接复用，无需改造。
- 复制成功反馈沿用现有 copied 动画与统一剪贴板写入逻辑（`clipboard.ts`），不另起炉灶。
